原题总要求

“Write a program that reads text from stdin, generates a score for each input line relative to a multi-term query supplied on the command-line, and ... prints out a set of input lines that have the highest scores.”

  • 查询由命令行提供：argv[1] 到 argv[argc-1] 是多个查询词。
  • 待搜索文本始终从 stdin 逐行读取；读到 EOF 后输出得分最高的行。
  • 核心知识点是数组、字符串、函数和 typedef；不允许文件操作，也不建议使用 malloc()。
  • 可以使用直接的实现方法及 string.h 中合适的函数，无需实现复杂模式搜索算法。

Stage 1 原题要求

“Modify the skeleton program so that the input text is read into an array.”

  • 最多 MAX_LINES = 999 行，每行最多 MAX_CHARS = 80 个字符；超出限制的输入可以静默丢弃。
  • 输出平均行长，然后输出第一行、最后一行以及它们各自的长度。
  • 行号从 0 开始。
核心实现一次读一行，再把每行放入二维数组
1. 读取一行read_one_line()
int read_one_line(line_t line, int max) {
    int len = 0, c;

    while ((c = getchar()) != EOF) {
        if (c == '\n') {
            line[len] = '\0';
            return len;
        }
        if (len < max) {
            line[len++] = c;
        }
    }
    if (len > 0) {
        line[len] = '\0';
        return len;
    }
    return EOF;
}
1为什么一直调用 getchar？

即使已存满 80 个字符，也要继续消耗本行到 \n，否则剩余字符会被错当成下一行。

2为什么手动写 \0？

C 字符串必须以 '\0' 结束；没有它，strlen 和 printf("%s") 会越界读取。

3为什么 EOF 前的最后半行也要保留？

文件最后一行可能没有换行符。只要 len > 0，它仍是一条有效输入行。

4为什么 line_t 需要 81 格？

80 格保存内容，第 81 格保存结束符。所以定义为 MAX_CHARS + 1。

一行在内存中的样子

f
u
n
.
…
[79]
\0

前 80 格是可保存字符的空间；最后一格专门留给字符串结束符。

2. 读取所有行read_lines()
int read_lines(lines_t lines) {
    int nlines = 0;
    line_t discard;

    while (nlines < MAX_LINES &&
            read_one_line(lines[nlines], MAX_CHARS) != EOF) {
        nlines++;
    }
    while (read_one_line(discard, MAX_CHARS) != EOF) {
        /* 超过 999 行的输入丢弃 */
    }
    return nlines;
}
5nlines 同时是数量和下一个空位

读入前 lines[nlines] 指向下一格；成功读入后再自增，不会出现 off-by-one。

6为什么还有第二个 while？

数组满后不再保存，但仍把 stdin 读到 EOF，完整实现“超出限制可丢弃”。

数据类型

typedef char line_t[MAX_CHARS + 1];
typedef line_t lines_t[MAX_LINES];
typedef int score_array_t[MAX_LINES];
typedef int index_array_t[MAX_LINES];

line_t 使用 MAX_CHARS + 1，多出的一格用于字符串结束符 \0。实际保存的行数为 nlines，合法行号是 0 ... nlines-1。

平均值怎么实现

\[\mathrm{average}=\frac{\sum_{i=0}^{nlines-1}\mathrm{strlen}(lines[i])}{nlines}\]
double average_length(lines_t lines, int nlines) {
    int total = 0;
    for (int i = 0; i < nlines; i++) {
        total += (int)strlen(lines[i]);
    }
    if (nlines == 0) {
        return 0.0;
    }
    return (double)total / nlines;
}
7为什么先检查 nlines == 0？

空输入时不能除以 0；直接返回 0.0 让函数始终有定义。

8为什么把 total 转成 double？

若两边都是 int，C 会先做整数除法，51.44 会被截断成 51。

关键边界：第一行是 lines[0]，最后一行是 lines[nlines - 1]；空输入时不能访问两者。

对每一行计算 prefix-match score

terms 为 fully 和 fun。

up to 16/20
Stage 2 原题要求

“Calculate a score for each input line in connection with the query provided on the commandline.”

  • 依次把行内每个字符位置当作匹配起点，计算它与所有查询词的最长连续前缀匹配长度 ℓi。
  • 匹配不区分大小写；每个字符位置都是每个 term 的潜在起点。
  • 按原题公式累加整行得分，并在 Stage 2 输出第一行和最后一行的分数。

从字符到整行分数：四层函数

核心实现小函数各做一件事，与数学定义逐层对应
1. 单个 term 的连续前缀匹配prefix_match()
int prefix_match(const char *text, const char *term) {
    int len = 0;

    while (text[len] != '\0' && term[len] != '\0' &&
            tolower((unsigned char)text[len]) ==
            tolower((unsigned char)term[len])) {
        len++;
    }
    return len;
}
1为什么在第一个不匹配处停止？

题目要的是 prefix：必须从起点连续向后相同。中间一旦断开，后面再相同也不属于前缀。

2为什么两边都 tolower？

实现 case-insensitive matching。先转成 unsigned char，再传给 tolower，符合 C 标准的参数要求。

2. 同一起点对所有 terms 取最大值position_match()
int position_match(const char *text, int argc, char *argv[]) {
    int best = 0;

    for (int argnum = 1; argnum < argc; argnum++) {
        int len = prefix_match(text, argv[argnum]);
        if (len > best) {
            best = len;
        }
    }
    return best;
}
3为什么 argnum 从 1 开始？

argv[0] 是程序名，真正的查询词从 argv[1] 开始。

4为什么取 max，不是相加？

原题把 ℓi 定义为该起点对所有 terms 的“最长”匹配。同一位置只能产生一次贡献。

3. 把匹配长度转成分数match_points()
int match_points(int match_len) {
    if (match_len > MAX_MATCH) {
        match_len = MAX_MATCH;
    }
    return (1 << match_len) - 1;
}
5为什么先封顶到 10？

这正是公式中的 min(ℓᵢ, 10)；匹配再长，单位置最多也只得 1023 分。

6为什么用 1 << n？

左移 n 位等于 (2^n)。C 中的 ^ 是按位 XOR，不是乘方。

4. 遍历整行每个起点line_score()
int line_score(const char *line, int argc, char *argv[]) {
    int score = 0;

    for (int i = 0; line[i] != '\0'; i++) {
        int match_len = position_match(line + i, argc, argv);
        score += match_points(match_len);
    }
    return score;
}
7line + i 是什么？

它是指向第 i 个字符的指针，因此每次都能把不同位置当作一个新的字符串起点。

8为什么遍历到 \0 为止？

只检查真实字符，不读取数组中未使用的空间，也不把结束符当成匹配起点。

定义

对一行中的每个字符位置 \(i\)，分别计算从该位置开始与所有 terms 的大小写不敏感前缀匹配长度，并取最大值 \(\ell_i\)。同一位置只使用最大值，不把多个 term 的匹配长度相加。

\[S=\sum_i\left(2^{\min(\ell_i,10)}-1\right)\]
函数返回值
prefix_match(text, term)一个起点与一个 term 的连续前缀长度
position_match(text, argc, argv)该起点对所有 terms 的最大匹配长度
line_score(line, argc, argv)该行所有起点贡献之和

STAGE 3

输出分数最高的五行

分数降序；同分时原始行号升序。

up to 20/20
Stage 3 原题要求

“Present the TOP_SCORES best-scoring lines.”

  • 输出 TOP_SCORES = 5 条得分最高的输入行。
  • 分数越高越先；如果两行同分，原始行号较小的先输出。
  • 全部输出的最后必须以 tadaa! 结束。

比较规则只有两层

第一层：比分数score 高的先
如果同分 →
第二层：比行号line number 小的先
核心实现只排序 order 里的行号，不搬动文本和分数
1. 把两层排序规则写成一个函数comes_before()
int comes_before(int left, int right, score_array_t scores) {
    if (scores[left] != scores[right]) {
        return scores[left] > scores[right];
    }
    return left < right;
}
1为什么分数使用 >？

题目要求降序，所以高分行应该出现在前面。

2为什么同分时使用 left < right？

left 和 right 就是原始行号。行号较小者优先，正好实现 tie-break。

2. 插入排序行号索引sort_indices()
void sort_indices(index_array_t order, score_array_t scores,
        int nlines) {
    for (int i = 0; i < nlines; i++) {
        order[i] = i;
    }

    for (int i = 1; i < nlines; i++) {
        int item = order[i];
        int j = i;
        while (j > 0 &&
                comes_before(item, order[j - 1], scores)) {
            order[j] = order[j - 1];
            j--;
        }
        order[j] = item;
    }
}
3为什么排 order，不排 lines？

order = [8,5,0,1,2,...] 只是一组行号。排它不会破坏 lines[i] 与 scores[i] 的对应关系。

4为什么插入排序就足够？

最多只有 999 行，题目明确允许 straightforward techniques。这个实现短、好验证、无需额外库。

3. 只输出前五个索引print_stage_three()
int nshow = nlines < TOP_SCORES ? nlines : TOP_SCORES;

for (int rank = 0; rank < nshow; rank++) {
    print_line_score(lines, scores, order[rank]);
}
5为什么用 min(nlines, 5)？

如果输入只有 3 行，就只输出 3 行；避免访问不存在的 order[3] 和 order[4]。

6rank 与行号为什么不同？

rank 是排名位置；order[rank] 才是原始行号。输出文本和分数都要用后者索引。
